## q'est-ce qu'elle apprend de nouveau?

1. Des informations d'exécution/génération concrètes

Le chemin réel sur disque (Location) et le fichier d'entrée (Entry file) du workspace — absents du script source qui ne fait que déclarer la configuration.
La date/heure de génération du rapport (Generated by jenga workspace on 2026-09-23 09:00:16).

2. Une ligne "Platforms" distincte

La commande info sépare Platforms: Windows de Target OSes: Windows, une distinction qui n'apparaît pas explicitement dans le script (qui ne définit que targetoses).

3. Le statut réel du projet dans un tableau récapitulatif

Le tableau Projects précise pour projet_salle des colonnes Test et External (toutes deux à No) — ces attributs ne sont pas déclarés du tout dans le script obtenu après build.

4. La liste des toolchains disponibles sur la machine

Le script ne fait que commenter une ligne # usetoolchain("host-gcc") sans détailler quoi que ce soit.
La commande info liste concrètement 3 toolchains détectés (host-gcc, msvc, mingw) avec leur Family, Target OS, Arch et Env — une information d'environnement réel, absente du script.

5. L'état du démon (Daemon)

Status: Not running — une information purement runtime/système qui n'a pas d'équivalent dans le fichier de configuration.
